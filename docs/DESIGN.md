# おつかいめいろ — 設計ドキュメント

> 4歳の姪っ子のための、超やさしいプログラミング体験の知育アプリ。
> マスの上でアバターを動かし、りんごや「おばあちゃんの家（実写真）」に届ける。届いたら**おじの声**で「ついたね!」。
> 絵本『ルビィのぼうけん』の延長として、**順序立て（アルゴリズム）**と**うまくいかない→直す（試行錯誤・デバッグ）**の下地をつくる。

最終更新: 2026-10-09

企画の全体像・案の比較は [IDEAS.md](IDEAS.md) を参照（本アプリは「案1 ○○ちゃんのおつかいめいろ」を第1作にしたもの）。

## 0. 配布方針（Webファースト・確定）

**決定: まず Web で配る。** Expo の web ビルド（静的サイト）を書き出し、その URL を姪っ子の端末（を持つ家族）に渡す。ブラウザで開き、**ホーム画面に追加**すれば、アドレスバーの無い全画面で“アプリのように”遊べる（iOS / Android とも対応）。ネイティブアプリ（App Store / Expo Go）は**同じコードから後日**出す。

- **なぜ Web ファーストか**
  - Apple Developer 登録（年約 $99）や審査なしで、**今すぐ実機で試せる**。身内配布・テスト段階に最適。
  - 端末を選ばない（iPhone / iPad / Android / PC どれでも URL 一つ）。姪っ子・祖母・おじの環境差を吸収できる。
  - Expo は同一コードから web / iOS / Android を出せるので、**Web 先行でも将来のネイティブ化は地続き**。
- **ホスティング: GitHub Pages** を想定。`npx expo export --platform web` で `dist/` を書き出し、Pages に載せて URL 配布（限定 URL でよい）。
- **渡し方**: URL を送る → Safari / Chrome で開く → 共有メニューから「ホーム画面に追加」→ アイコンから全画面起動。
- **オフライン性は維持**: バックエンド・アカウント・通信は引き続きゼロ。初回だけ静的アセットを取得し、**写真・音声・進捗は端末内（ブラウザ内）に留める**。§1「完全オフライン」の方針は Web でも保つ（サーバへ送らない）。将来 Service Worker を足せば再訪時の完全オフライン起動も可能（MVP 対象外）。

## 1. コンセプト

受け身の「見る」から、**自分で考えて動かす**へ。それを4歳が、コードもリアルタイム操作も使わずに体験できる形にする。

- **核となる体験:** マス目の世界でアバターを目的地まで動かす。届いたら大歓声、外れてもキャラが首をかしげるだけ。
- **育てたい力:** ①言われた順に物事を並べる（順序立て）、②思ったとおりにいかなかったら直す（試行錯誤）。就学後に必修化される「順序・くりかえし」の入口。
- **キャラ設定:** アバターは「**言われた順にしか歩けないおともだち**」。だから間違いは“ロボットの正直な実行”として腹落ちする（＝デバッグの原体験）。

### この子だけの世界地図（最大の差別化）

作り手（おじ）と姪っ子は遠方でほとんど会わない。汎用アプリには絶対に作れない要素で埋める。

- ゴールを**実在の写真**（祖母の家・この前いった公園）に。
- 掛け声「ゴー!」「ついたね!」を**おじの録音声**に。
- 主役は姪っ子本人（既存キャラIPは使わない）。

### 立ち位置（重要・2つの前提）

| 前提 | 中身 |
|---|---|
| **プライバシー: 完全オフライン** | MVPは**単一端末で完結**。写真・音声・進捗はすべて**端末内のみ**に保存し、**外部送信・アカウント・通信はゼロ**。これが1本目（kore-daijobu）との一番の違い。 |
| **著作権** | アンパンマン等の既存キャラは不可。素材は**自作／AI生成／フリー素材（いらすとや等）／おじの録音**のみ。 |

## 3. 二段階の遊びモード（本アプリの背骨）

4歳には「先にまとめて計画する」がやや難しい。そこで**やさしい方から2段階**で用意し、MVPは①だけを作り切る。

| | ① タップで即動く【MVP】 | ② ならべてゴー（キュー方式） |
|---|---|---|
| いつ | 最初から | ①に慣れてから（フェーズ4・**実装済み** → §16） |
| グリッド | 2×2〜3×3 / 1〜2手 | 3×3〜 / 数手 |
| 操作 | 方向ボタン → その場で1マス動く | 矢印を並べる → 「ゴー!」で一気に実行 |
| 体感 | 押す→動く（因果・空間把握） | **計画→実行→観察→修正**のループ |

> **切替は おとなモードの「あそびかた」トグル**（保存キー `meiro.mode`・既定 `'tap'`）。
> 親が有効化するまで、こども側の見た目・挙動はフェーズ1と完全に同一（→ §16.5）。

②のプログラミング的思考ループ:

```
   けいかく          じっこう          かんさつ          しゅうせい
  （ならべる）  →  （ゴー!）  →  （とどいた?）  →  （ならべ直す）
        └────────────────── くりかえし ──────────────────┘
```

> ①でも「押す＝1つの命令」を体で覚えるので、②への地続きの前段になる。②は同じ移動処理・同じレベルデータをそのまま使い、UI（命令キュー）だけ足す設計にする。

## 4. 4歳UX原則（全画面の共通ルール）

- **文字に頼らない** … 操作は音声・アイコン・写真で伝える。ひらがなは“読める子には嬉しい”装飾程度。
- **巨大タップ領域** … 方向ボタンは指1本で確実に押せる大きさ（実装上64pt以上、実際はもっと大きく）。押し間違い防止に間隔をあける。
- **単発タップ中心** … こども操作にドラッグ・長押しを使わない（親ゲートを除く）。指の接触切れに強い。
- **誤操作に寛容** … 動けない方向を押しても何も壊れない。Undoが要らない設計。
- **罰・ゲームオーバーなし** … タイマー・ライフ・減点なし。外れ＝「もういちど」の入口。失敗表現はキャラが**首をかしげる**だけ。
- **短いセッション** … 1レベル数十秒。いつでも中断・再開。連続プレイを煽らない。
- **過度な射幸性なし** … ガチャ・コイン・ランキング・広告なし。ご褒美は「写真＋おじの声＋ちいさな演出」に限定。
- **感覚にやさしく** … 強い点滅・大音量・急な動きを避ける。音量は控えめを既定に。

## 5. MVP スコープ

### コアループ（これ1つを作り切る）

```
レベルをえらぶ
  → 方向ボタンをタップ → アバターが1マス動く（①タップモード）
  → ゴール（りんご/写真）に届く
  → 写真ズーム＋ちいさな紙吹雪＋おじの声「ついたね!」
  → 「もういちど」/「つぎへ」
```

### やること（MVPに入れる）

- ①タップモードのプレイ画面（グリッド描画・アバター・方向ボタン・1マス移動・障害物と壁の判定）
- ゴール到達 → 祝福演出（既定でも成立：既定イラスト＋既定SE）
- **むずかしさテンプレート5個**（2×2→4×4へゆるやかに）から迷路を**その場でランダム生成**（さんすうドリルのように何度でも遊べる）＋ **レベルえらび**画面
- **おとなモード（親ゲートの奥）: ゴール写真の差し替え**（＝差別化の核。必須）
- 端末内保存（上書きした写真・音声のパス、任意で進捗）

### やること・努力目標（できれば入れる）

- **おじの声の録音／差し替え**（expo-audio）。※録音UIが最大の新規リスクなので、**まずは事前収録した音声ファイルを同梱**して鳴らす形で成立させ、録音UIは余力があれば。
- ハプティクス（タップ・到着の触覚）
- ごく短いBGM

### やらないこと（MVPでは入れない = 次段階）

- ②キュー方式（並べてゴー）… フェーズ4 → **実装済み（§16）**
- 「くりかえし（ループ）」ブロック … 将来
- **おとなモードでのレベル構造の編集**（マス・障害物のGUI編集）… 当面レベルはJSON同梱で、追加・変更はコード側で行う
- 進捗ロック（前をクリアしないと次に行けない等）… MVPは全レベル自由に遊べてよい
- **ネットワーク・バックエンド・アカウント全般**（遠隔レベル送信は第2フェーズ）

### こども側（文字ゼロで進める）

```
[タイトル]
  左上に「まちへ もどる」（木の絵＋ひらがな）… ぴよぴよランド（街・同じオリジンの /）へ戻る。web のみ・タイトルにだけ置く
  大ボタン「あそぶ」（アイコン＋読み上げ）
  隅にちいさな歯車 … 3秒長押しで [おとなモード]（親ゲート）
  　　　　　　　　　 キーボードでは歯車にフォーカスして Enter / Space の長押し（3秒）でも開く
     │ タップ
     ▼
[レベルえらび]   ※「むずかしさカード」を横スクロール。各カードはミニめいろ（マスの大きさ・🌳の数）で
                   むずかしさを一目で伝える。ゴール絵文字は固定しない（遊ぶたびランダムに変わるため）。
     │ カードをタップ → その難易度の迷路をその場でランダム生成
     ▼
[プレイ（①タップモード）]
  上段: そのプレイのゴール絵文字（「ここまで いこう」＋🍎/🏠/🍰… のいずれか）
  中段: 2×2〜4×4 のグリッド ＋ アバター（＋障害物）。配置は毎回ランダム（BFSで到達可能を保証）
  下段: ◀ ▲ ▼ ▶ の巨大ボタン
     ・押す → 動ける向きなら1マス移動（てくてくSE）

     ・ゴール到達 → 写真ズーム＋紙吹雪＋おじの声「ついたね!」
     │
     ▼
[クリア]  「もういちど（＝同じ難易度で新しい迷路）」／「つぎへ」／「おうちへ（レベルえらび）」
```

### ②キュー方式（フェーズ4での差分だけ・実装済み → §16）

```
[プレイ（②ならべてゴー）]
  上段     : 🏠 ／「ここまで いこう」＋ゴールの絵（①と同じ）
  命令の列 : ▶ ▶ ▶ ▼ ▼ □ □ □ □ □   ⌫    ← 押した矢印が左から積まれる。空きマスも見せる
  中段     : めいろ盤面（①とまったく同じ）
  下段     :        ▲
                 ◀ (ゴー!) ▶              ← 十字のまんなかが「ゴー!」（Bee-Bot 流）
                    ▼

  下段の矢印を押す → その場では動かず「命令の列」に積まれる
  「ゴー!」→ 先頭から1マスずつ実行（アニメとSEを同期。いま動いている命令が光る）
  動けない歩は首をかしげるだけで **実行は止めない** → 届かなければスタートへ ぴょんと戻り、列は空

```

## 7. データモデル

**「むずかしさテンプレート」を同梱JSONで**持ち、レベル（1つの迷路）は**選ぶたびに実行時ランダム生成**する。写真・音声パスは端末内のみ。さんすうドリルのように、同じカードでも毎回ちがう迷路が出て**何度でも遊べる**（ユーザーの意図「さんすうのように何回も遊べるようにしたい」）。

### むずかしさテンプレート（アプリ同梱の静的JSON `templates.json`）

レベルえらびの5枚のカード ＝ 5つのテンプレート。カードは「固定レベル」ではなく**難易度の型**を表す。①2×2 →⑤4×4 と、マス数と障害物数がゆるやかに増える。

```jsonc
{
  "id": "level-01",           // 進捗(⭐)のキー。カードの並び順の識別子
  "label": "ちいさな めいろ",  // カードの見出し（ひらがな。むずかしさが伝わる表現）
  "cols": 2,                  // 横のマス数
  "rows": 2,                  // 縦のマス数
  "obstacleMin": 0,           // 生成時に置く障害物の最小数
  "obstacleMax": 0,           // 生成時に置く障害物の最大数
  "minSteps": 2               // 生成する迷路の最短手数の下限（近すぎるゴールを防ぐ）
}
```

同梱テンプレート（`src/data/templates.json`）:

| # | label | マス(列×行) | 障害物 | minSteps |
|---|---|---|---|---|
| ① | ちいさな めいろ | 2×2 | 0 | 2 |
| ② | ちょっと おおきい | 3×2 | 0〜1 | 3 |
| ③ | きの ある めいろ | 3×3 | 1 | 4 |
| ④ | きが おおい めいろ | 3×3 | 2 | 4 |
| ⑤ | おおきな めいろ | 4×4 | 2〜3 | 5 |

> ⭐（進捗）は**テンプレート単位**のまま。id は旧固定レベルと同じ `level-01`〜`level-05` を踏襲するので、既存の `meiro.stars` 保存とも互換。カード＝「くり返し挑戦するドリルの1ページ」の位置づけ。

### 迷路の生成（`src/game/generate.ts`・実行時）

カードを選んだ瞬間、テンプレートからスタート・ゴール・障害物・**ゴール絵文字**（🍎🏠🍰🍓🎈🍦…のプールから毎回1つ）をランダムに決めて1つの迷路（`Level`）を作る。生成された `Level` の `id` は**テンプレートidをそのまま持つ**（生成迷路が変わっても⭐のキーは不変）。「もういちど」は**同じ難易度の新しい迷路**を作り直す。`Level` の構造（`start`/`goal`/`obstacles`/`goalEmoji` …）は従来どおりで、移動ロジック（`maze.ts`）・盤面描画（`MazeGrid`）はそのまま動く。

**安全保証（4歳向けに「詰み」・無限ループ・クラッシュを絶対に出さない）:**

1. 生成した迷路は必ず **BFS で到達可能性を検証**する（届かないなら不採用）。
2. **最短手数が `minSteps` 以上**になるまで作り直す（近すぎるゴールを防ぐ）。
3. 作り直しは**上限つき**（1段あたり最大50回）。溢れたら障害物を段階的に減らして再挑戦し、それでも駄目なら「**対角コーナー・障害物ゼロ**」の決定的フォールバックを返す。
   - 不変条件 `minSteps ≤ (cols−1)+(rows−1)` を全テンプレートで満たすので、この最終手段は**必ず**成立する（＝どんな乱数でも必ず遊べる迷路を返す）。
4. 乱数は `Math.random`（実行時コード。外部送信なし）。

> **プロパティ検証済み:** 各テンプレートで1,000個（さらに10,000個 ＝合計50,000個でも）生成し、**すべて (a) BFS到達可能 (b) 最短手数≥minSteps (c) スタート≠ゴール・障害物と非重複**を満たすことをスクリプトで確認。フォールバック（対角コーナー）が発火した例は0件（ほぼ全数が自然生成）。

**座標と移動の約束:** `x` は列（左→右）、`y` は行（上→下）、どちらも0起点。▲=y−1／▼=y+1／◀=x−1／▶=x+1。盤面の外・障害物のマスへは移動しない（＝首をかしげる）。

### おとなモードの上書き（web = IndexedDB。実装済み → §15）

同梱JSONは書き換えず、**差分だけ**を端末内に保存して重ねる。フェーズ2の実装では、写真・録音は
**IndexedDB（DB名 `meiro-personal`）**に Blob のまま入れる。`Level.goalImage` には、起動時に作った
その Blob の `blob:` URL がプレイ単位で入る（詳細は §15）。

```jsonc
// IndexedDB: meiro-personal / photos （keyPath 'id'）
{ "id": "p…", "blob": <Blob>, "mime": "image/jpeg", "width": 512, "height": 341, "createdAt": 1754… }
// IndexedDB: meiro-personal / voices （keyPath 'slot'）
{ "slot": "tsuita", "blob": <Blob>, "mime": "audio/webm;codecs=opus", "createdAt": 1754… }
```

> ネイティブ版では `expo-image-picker` / `expo-audio` / `expo-file-system` に置き換える余地を残す
> （`personal/` 配下の各モジュールは `Platform.OS !== 'web'` で「つかえない」を返すだけのスタブになる）。

### 保存場所とプライバシー

| データ | 保存先 | 外部送信 |
|---|---|---|
| むずかしさテンプレート（構造） | アプリ同梱JSON（迷路は実行時にランダム生成） | しない |
| ごほうび（⭐スタンプ） | web は `localStorage`（`meiro.stars` / `meiro.celebratedAll` / `meiro.totalStars`）。native はセッション内キャッシュのみ（→ §14） | **しない** |
| BGM の ON/OFF | `localStorage`（`meiro.bgm`） | **しない** |
| あそびかた（①/②） | `localStorage`（`meiro.mode`。`'queue'` のときだけ②。既定 `'tap'`。→ §16） | **しない** |
| ゴール写真 | web は **IndexedDB `meiro-personal` / `photos`**（長辺512pxのJPEGに縮小した Blob。最大6枚） | **しない** |
| おじの声 | web は **IndexedDB `meiro-personal` / `voices`**（録音 Blob ＋ mime。スロット `tsuita` / `zenbu`） | **しない** |

> **すべて端末内で完結。通信・アカウント・クラウドは一切使わない。** カメラロールの写真は
> 「アプリ内に縮小コピーを1枚持つ」だけで、どこにも送らない。DB名で名前空間を分けているので、
> 同一オリジン（`kerokero-1245.github.io`）に同居する姉妹アプリのデータとも混ざらない。

## 8. 技術構成

1本目 kore-daijobu と**同じスタックを再利用**（Expo SDK 57 / React Native / TypeScript、`src/screens`・`src/components`・`src/data` 構成、Node 22.23.3）。バックエンド（Supabase）は**使わない**。

### Web対応の注意（Webファースト前提 / §0）

Expo は同一コードを web でも動かせるが、ブラウザ特有の制約がある。§0 の配布方針に伴い、以下を織り込む。

- **音声の自動再生制限（iOS Safari 等）** … ページ読み込み直後に勝手に音は鳴らせない。**ユーザーのタップを起点にした再生なら鳴る**ので、SE・掛け声は「ボタンを押した」「到着した（＝直前の操作起点）」タイミングで鳴らす設計にする。BGM の自動ループは避けるか、最初のタップで解禁する。
- **端末内保存の永続性** … RN の `AsyncStorage` は web では **`localStorage` 相当**になる。プライベートブラウズ・サイトデータ削除・ストレージ逼迫で**消える可能性**がある。MVP は「消えても遊びが壊れない」前提（進捗ロックなし）なので許容。写真・録音は容量が大きく `localStorage`（文字列・5MB前後）に載らないため、**IndexedDB** を使う（→ §15）。IndexedDB が使えない環境でもクラッシュさせず、機能を静かに無効表示する。
- **写真・録音の取得** … expo-image-picker / expo-audio はネイティブ API 前提。web では **ブラウザ API（`<input type=file>` / `getUserMedia` / MediaRecorder）経由**になり、挙動・権限 UI が異なる。**フェーズ2で web 実装を用意した（→ §15）。** 新規 npm 依存はゼロ（ブラウザ標準APIのみ）。
- **画面向き** … web はブラウザが向きを固定しないため、**縦持ち前提のレイアウト**（中央寄せ・最大幅制限）で横画面でも崩れないようにする。
  - タイトルは上に「まちへ もどる」の行（高さ 44＋余白）を取り、題字〜「あそぶ」と歯車の行はその下に流す（重ねない）。背の低い横向き（844×390・568×320 など）では全体がスクロールして全部に届く。
  - タイトルの題字の大きさは「1 字 = 1em ＋字間」で枠の幅から見積もる（ぴよぴよさんすう・ことばと同じ式）。かなが全角の書体でも 320 幅で 1 行（42px）、390・360 幅は 44px のまま。
  - 「まちへ もどる」は `href="/"` を持つ本物のリンク（`<a>`）。Tab の最初のフォーカスで、Enter・Space・クリックのどれでも街へ移る（`src/components/TownLink.tsx`）。
  - 「まちへ もどる」の絵は、街の 404 ページと同じ自作 SVG の木（`assets/piyo/ki.svg` ＝ 街の `/assets/img/ki.svg` と同じファイル）。絵 → 文字の並びも同じ。
  - クリア画面（ついたね!）の中身はスクロールできる入れ物に入れる。縦持ちで画面に収まるときは従来と同じ位置、収まらない画面（320×568・横向き）ではスクロールで「もういちど」「つぎへ」「おうちへ」の全部に届く。

- リポジトリ名は `otsukai-meiro`（アプリ名「おつかいめいろ」確定に伴いリネーム済み）。

## 14. ごほうび（スタンプ式・実装済み）

4歳UX原則（§4「罰・ゲームオーバーなし」「過度な射幸性なし」）を守るごほうび。**数字スコアではなく⭐スタンプ**で、マイナス要素はゼロ。

### 方針

- **クリア = ⭐**。何手で着いたか・最短かは**一切問わない**。ゴールに着いたら、そのレベルに⭐が付く。
- **剥奪しない・減らない**。既にクリア済みのレベルを再クリアしても変化なし。失敗・減点・タイマー・「まだ無い」の表示は出さない。
- **「未達成マーク」を出さない**。未クリアのレベルは**空欄**（灰色の星などは置かない）。「まだ持っていない」を意識させないため。

### 見え方

| 場面 | 何が起きるか |
|---|---|
| **クリア演出**（`ClearOverlay`） | ゴールがぽんっと拡大したあと、⭐が弾んで付く「⭐ゲット!」の瞬間（`star` 効果音つき）。毎回出る（再クリアでも祝福だけ）。 |
| **レベルえらび**（`LevelSelectScreen`） | クリア済みカードの右上に⭐バッジ。未クリアは何も出さない。全部⭐なら見出しに控えめな👑。 |
| **ぜんぶ できたね! がんばりカード**（`GanbariScreen`） | 全5レベルの⭐が**初めて揃った瞬間に一度だけ**。⭐×5が順に並び→👑と大きな「ぜんぶ できたね!」＋紙吹雪＋`fanfare`。以降は出さず、レベルえらびの👑で余韻を残す。 |

### 保存と実装

- 状態は web の `localStorage` に保存（`piyopiyo-sansu/src/settings.ts` の localStorage パターンを移植 → `src/progress.ts`）。native はセッション内キャッシュのみ（フェーズ2で `AsyncStorage` に差し替え可能）。**外部送信ゼロ**。
- キー: `meiro.stars`（クリア済みレベルidの配列）/ `meiro.celebratedAll`（がんばりカードを見せたか）/ `meiro.totalStars`（累計クリア回数。街＝ランチャーの燃料）。
- `meiro.totalStars` は**クリアのたび +1**（再クリアも +1）。キー未存在の初回だけ既存 `meiro.stars` の件数を初期値に書き込む（マイグレーション）。**「⭐をリセット」ではバッジは消すが `totalStars` は残す**（街の成長を巻き戻さないため）。街（別オリジンではなく**同一オリジン**の `kerokero-1245.github.io` 直下ランチャー）は `Number(meiro.totalStars||0) + Number(sansu.totalStars||0)` を燃料に読む。
- **消えても遊びは壊れない**（進捗ロックは無いまま／§5）。プライベートブラウズやサイトデータ削除で消える可能性は許容（§8 web 注意）。
- **リセット**は「⭐をリセット」としておとなモード（親ゲートの奥）に配置。子どもの誤操作を避けるため確認を1枚はさむ。
- 効果音はすべて `src/audio/sounds.ts` に Web Audio で合成（外部素材ゼロ）。`star`（きらっ）と `fanfare`（大祝福）を追加。§8 のとおり音は必ずタップ／到着起点で鳴らす。

> **レイアウト不変**: 追加UIはオーバーレイ／絶対配置バッジ／独立画面で足しており、プレイ画面の高さバジェット計算（ヘッダー＋盤面＋方向パッド、commit 5bed703）は変更していない。背の低いウィンドウ（515×684）でも被りゼロを維持する。

## 15. パーソナライズ ＝ この子だけの世界地図（フェーズ2・実装済み / web）

§1「この子だけの世界地図」を実際のコードにしたもの。**ゴールを実在の写真に、クリアの声をおじの録音に**
できる。汎用アプリには作れない、このアプリの差別化の核。

**絶対条件: 完全端末内・外部送信ゼロ。** 通信・アカウント・クラウドは一切使わない。写真も録音も
IndexedDB とメモリ上の `blob:` URL にしか存在せず、いつでも消せる。

### 15.1 何ができるか（おとなモード＝⚙️3秒長押しの奥）

| セクション | できること |
|---|---|
| **ゴールの しゃしん** | 写真を**最大6枚**追加（`<input type="file" accept="image/*">`・複数選択可）。サムネイル一覧から**1枚ずつ削除**、**ぜんぶ削除**。 |
| **こえ** | 「ついたね!」「ぜんぶ できたね!」の2スロットを**録音**（最長6秒・自動停止）。**ためしぎき**（実際の再生経路を通す）・**とりなおす**・**削除**。 |
| **プライバシー表示** | 画面の一番上に「しゃしんと こえは この たんまつの 中にだけ ほぞんされます。」＋「どこにも おくりません…いつでも けせます。」 |

破壊的操作（1枚削除／ぜんぶ削除／録音削除／⭐リセット）には**確認を1枚**はさむ（§6）。
**こども側の UI には何も足していない**（§4 の原則を維持）。

### 15.2 ゴール写真

- **保存前に必ず縮小**する（`src/personal/image.ts`）。長辺 **512px**・**JPEG 品質0.8**。1枚おおむね
  5〜120KB。EXIF の向きは `createImageBitmap(file, {imageOrientation:'from-image'})` で正し、
  非対応環境は `<img>` 経由にフォールバック。
- 写真が1枚以上あるとき、**そのプレイのゴールが写真になる確率 = 2/3**（`PHOTO_GOAL_CHANCE`）。
  残り 1/3 は従来どおり12種のシールポップ絵。「おばあちゃんの家がゴール」の感動を優先しつつ、
  「毎回ちがう」楽しさも残すため。複数枚あればその中から毎回ランダム。
- 描画は `src/components/GoalArt.tsx` に集約。**白フチ・角丸・やわらかい影**のシール風にして、
  既存のシールポップSVGと同じ空気にそろえる。
  - マスの上・上段バナー … `resizeMode='cover'`（正方形にきれいに収まる）
  - クリア演出のズーム … 丸ではなく**白い台紙の角丸四角**＋`resizeMode='contain'`（家や人が欠けない）
- 読み込みに失敗したら（消えた `blob:` URL など）`onError` で**静かに絵文字/SVGへ戻す**。

### 15.3 おじの声

- `getUserMedia` + `MediaRecorder`（`src/personal/recorder.ts`）。mime はブラウザで違うので
  `isTypeSupported` で `audio/webm;codecs=opus` → `audio/webm` → `audio/mp4` … の順に選び、
  **採用した mime を録音と一緒に保存**する。再生は `blob:` URL 経由。
- 再生の優先順位は voice.ts の**4段構え**に拡張した:
  **⓪ おじの声（録音）→ ① 同梱クリップ（VOICEVOX ずんだもん）→ ② speechSynthesis → ③ 無音**。
  録音があれば `p_tsuita` / `p_zenbu` の**代わりに**鳴り、無ければ従来どおり。
  再生は同梱クリップと**同じ経路**（`clips.ts` の `playAudioUrl`）を通るので、**BGM ダッキングも同じ**。
- マイクは `getUserMedia` に1秒以上かかることがある。**準備が終わるまで「とめて ほぞん」を出さない**
  （「⌛ マイクを ひらいています…」を表示）。押したのに保存されない、を作らないため。
- 最長6秒で自動停止。停止時・画面離脱時は必ずマイクのトラックを止める（録音インジケータを残さない）。

### 15.4 保存（IndexedDB）

- DB名 **`meiro-personal`**（v1）。ストアは `photos`（keyPath `id`）と `voices`（keyPath `slot`）。
  同一オリジンの姉妹アプリと混ざらないよう**DB名で名前空間を分ける**。
- ラッパは `src/personal/idb.ts`。**どの API も例外を投げない**（失敗は `null` / `[]` / `false`）。
  - `open` に**4秒のタイムアウト**を張る（固まる環境で待ち続けない）。
  - 書き込みの成否は**トランザクションの commit** で判定する（リクエストの `onsuccess` は commit 前に
    鳴るので、容量超過などで後からアボートしたのを取りこぼさないため）。
- 在庫は `src/personal/store.ts` がメモリに持つ（`blob:` URL 付き）。迷路生成もクリア演出も同期処理
  なので、`App.tsx` のマウントで一度 `initPersonal()` して**同期で引ける形**にしておく。

### 15.5 壊れないこと（フォールバックの一覧）

| 状況 | 起きること |
|---|---|
| IndexedDB が無い／開けない（プライベートブラウズ等） | おとなモードの2セクションが「この ブラウザでは …できません。めいろは これまでどおり あそべます。」に変わるだけ。**こども側は完全に従来どおり**（絵文字ゴール・ずんだもん） |
| 写真の読み込み失敗 | `GoalArt` の `onError` で絵文字/SVGへ戻す |
| 写真が0枚 | ゴールは12種の絵文字プールへ**完全復帰** |
| 録音が無い／読めない | `p_tsuita` / `p_zenbu`（ずんだもん）→ speechSynthesis → 無音 |
| マイク権限の拒否 | 「マイクを つかえませんでした（きょかを かくにんしてください）。」を出すだけ |
| 画像が縮小できない | 「この しゃしんは つかえませんでした。」を出すだけ（保存しない） |

## 16. ②ならべてゴー ＝ やじるしモード（フェーズ4・実装済み / web）

§3「二段階の遊びモード」の②を実際のコードにしたもの。IDEAS.md 案1 の核である
**けいかく（ならべる）→ じっこう（ゴー!）→ かんさつ（とどいた?）→ しゅうせい（ならべ直す）** の
ループを、4歳が指1本で回せる形にした。アバターは「言われた順にしか歩けないおともだち」なので、
外れたのは**ロボットの正直な実行**であって、こどもの失敗ではない（§1）。

**既定は① のまま。** おとなモードで有効にするまで、こども側の見た目・挙動はフェーズ1と
**完全に同一**（変更前ビルドと DOM が一致することを実測で確認 → §16.6）。

### 16.1 遊びの流れ

| 操作 | 起きること |
|---|---|
| 下段の ◀▲▼▶ を押す | **その場では動かない**。上段の「命令の列」に矢印が1つ積まれる（「ぽん」）。 |
| 列の右の **⌫** を押す | さいごの矢印が1つ消える。列が空のときは うすく表示して押せない。 |
| 上限まで積んだあと押す | **何も起きない**（音も出さない）。空きマスが無いことで「いっぱい」が見える（§4 エラー表現なし）。 |
| まんなかの **ゴー!** を押す | 先頭から1マスずつ実行。1歩260ms＋歩の間110msで、**1つずつ動いている**のが目で追える。 |
| 実行中 | いま動いている命令が**緑に光り**、済んだ命令は**うすく**なる。方向パッド全体もうすくなり押せない（＝いまは見るじかん）。 |
| 動けない歩（壁・障害物） | やさしい「?」音＋首をかしげる。**実行は止めず、残りの命令も順に実行する。** |
| 途中でゴールに着いた | 残りの命令は**捨てて**すぐクリア演出（余分に並べたことを罰しない）。 |
| 全部実行しても届かない | 少し間をおいて首をかしげ → スタートへ**ぴょんと戻り** → 列は空になる。もう一度組み直せる。 |

**罰は一切ない**（§4）: タイマー・ライフ・減点・「まちがい」の表示は無い。⭐は減らない。
届かなかった回は「もういちど」を押す必要すら無く、そのまま組み直せる（＝修正ループが最短）。

### 16.2 画面（下段の作り）

「ゴー!」は**十字のまんなか**に置いた。

- Bee-Bot / Cubetto など同年代向けのプログラミング玩具と同じ配置で、指が自然に届く。
- 方向ボタンと同じ一辺なので巨大タップ領域（§4）を満たす。
- 画面の縦を1段も使わないので、**盤面のマスを大きいまま保てる**（帯のほかにもう1段ボタンを
  置くと、背の低い 515×684 では 4×4 のマスが下限の44pxでも収まらなくなる）。
- 見た目は**緑のまる**にして、オレンジの角丸（＝矢印）とはっきり分ける。矢印が0本のあいだは
  うすく押せないので、「まず ならべる → それから ゴー!」の順番が文字なしで伝わる。

**縦の配りかた**（`PlayScreen.tsx`）。②では「命令の列」の帯が1段増えるが、
**タップ標的の大きさは あそびかたで変わってはいけない**（§4）ので、帯が食う縦は
**優先度の低いほうから** 返す:

> タップ標的（方向ボタン・ゴー!・⌫）　＞　盤面のマス　＞　帯のマスの見た目

＝ 帯の高さは**方向パッドの取り分からは引かず、盤面から引く**。唯一の例外は「盤面が下限44pxの
マスすら置けない」ほど縦が足りない画面で、そのときだけ足りないぶんを方向パッドが譲る（重なり防止を最優先）。
以前は帯のぶんを先に引いてから方向パッドを決めていたため、②だけボタンが下限の52pxに張り付いていた。

実測（4×4・①=タップ / ②=ならべてゴー・単位px）:

| ビューポート | ①方向ボタン | ②方向ボタン | ①マス | ②マス | ②の帯 |
|---|---|---|---|---|---|
| 390×844 | 87 | **87** | 86 | 80 | 64 |
| 515×684 | 66 | **66** | 77 | 58 | 64 |
| 1280×800 | 81 | **81** | 93 | 74 | 64 |
| 360×640 | 61 | **61** | 70 | 51 | 64 |

（2026-10-06 に再計測。盤の外寸を「マス目全体＋枠線 3px×2」に直し、マスの大きさも枠線のぶんを
引いてから割るようにしたため、マスは以前の値より段数によって最大 3px 小さい。方向ボタン・帯は変わらない。
以前はマス目が枠線の内側より 6px 大きく、右と下の枠線にかぶっていた。）

②の方向ボタンと「ゴー!」は、どの画面でも**①と同じ一辺**（＝64px以上。360×640 だけは①自体が
61pxなのでそこまで）。⌫ は **64×64 の実寸**で確保する — react-native-web は `hitSlop` を
**無視する**（実測）ので、当たり判定はボタンの箱そのものでなければならない。

「命令の列」は**上限ぶんの空きマスも表示する**。あと何本置けるか・いっぱいになったかを、
文字を使わずに見せるため（未達成マークは出さない §14 の流儀に合わせ、空きマスはうすい下地だけ）。
帯の高さは**上限本数によらず 64px 固定**（＝⌫ の一辺）。矢印のマスは表示だけなので、
その一定の高さと横幅の両方に収まる中で**いちばん大きくなる並べ方**を選ぶ（1行に入るなら1行、
入らなければ2行に折り返す / `measureQueueStrip`）。以前は「1行7個まで・1マス最大44px」だったため、
上限9〜10本（⑤の92%を占める最頻ケース → §16.4）が 2行×44px＝**帯96px** になり、
360×640 では上限14本（2行×29px＝帯66px）より30pxも厚い、という逆転が起きていた
（＝いちばんよく出る迷路がいちばん盤面を損する。実際 360×640 の4×4は 上限9本でマス52px、
上限14本で59px と逆転していた）。高さを一定にしたことで、この非単調は消えた。

### 16.3 共通なもの（②が足すのは UI だけ）

レベルえらび・むずかしさテンプレート・**迷路のランダム生成**・移動判定（`maze.ts` の
`move`/`canMove`/`isGoal`）・⭐（`progress.ts` の同じキー）・クリア演出（`ClearOverlay`・
おじの声／ずんだもん）・「もういちど」＝同じ難易度で新しい迷路 は、**①と完全に共通**。
生成器はモードを知らないので、①でも②でも**同じ迷路が出る**（あそびかたは `Level` に持たせない。
端末の設定 `meiro.mode` をプレイ画面が読んで描き分けるだけ）。

### 16.4 並べられる矢印の上限（なぜ固定10本ではないか）

上限は `Level.maxSteps`。**その迷路の実際の最短手数 ＋ よゆう4本、最低6本**（`generate.ts` の
`queueCapacity`）。全配置を全数探索したところ、採用されうる最短手数の最大は

| テンプレート | ① 2×2 | ② 3×2 | ③ 3×3 | ④ 3×3 | ⑤ 4×4 |
|---|---|---|---|---|---|
| 最短手数の最大 | 2 | 4 | 4 | 6 | **10** |

で、⑤は最短10手の迷路が（まれに）起こりうる。固定10本にすると、その迷路では
「一本道の完璧な10手」しか許されず、まわり道もやり直しの余白も無くなる。上限は
**盤面の最短手数に対して十分な数**でなければならないので、生成時に判明した最短手数から
1迷路ごとに決めている。

実際に出る上限本数の分布（各テンプレート 200,000 回生成の実測）:

| テンプレート | 上限本数の分布 |
|---|---|
| ① 2×2 | 6本 100% |
| ② 3×2 | 7本 89.0% / 8本 11.0% |
| ③ 3×3 | 8本 100% |
| ④ 3×3 | 8本 72.0% / 9本 18.8% / 10本 9.3% |
| ⑤ 4×4 | **9本 68.5% / 10本 23.2%** / 11本 5.1% / 12本 2.1% / 13本 0.7% / 14本 0.3% |

＝ 全体では 6〜14本。⑤は 9〜10本で92%を占めるので、帯のレイアウトはこの本数で
**いちばん損をしない**ことが大事になる（→ §16.2 で帯の高さを一定にした理由）。

### 16.5 モードの切替と保存

- おとなモード（⚙️3秒長押しの奥）の「**あそびかた**」トグル。`① タップで すすむ` ⇄
  `② ならべて ゴー!`。BGM トグルと同じ UI の作法。いつでも戻せる。
- 保存は `localStorage` の **`meiro.mode`**（`'queue'` のときだけ②。未設定・壊れた値・
  読めない環境はすべて `'tap'`）。**外部送信ゼロ**（§7）。消えても既定の①に戻るだけ。
- プレイ画面は**入った時点の設定で固定**する（遊んでいる最中に切り替わらない）。おとなモードから
  戻ると タイトル→レベルえらび→プレイ と入り直すので、切替は必ず次の迷路から効く。

### 16.6 壊れないこと・やさしさ

| 観点 | どうしたか |
|---|---|
| **①のリグレッション** | ②の追加は「帯を1つ足す」「十字の中央に子要素を1つ置く」だけ。既定（`mode='tap'`）では変更前ビルドと **DOM が完全一致**（タイトル／レベルえらび／プレイ 2×2・4×4・移動後 × 390×844・515×684・1280×800 の15スナップショットで実測。差は常時アニメしている要素の位相のみ）。 |
| **音** | 新しい音声クリップ・録音機能には一切触っていない。矢印/⌫/ゴー! は既存の `tap`、1歩は `move`、動けない歩は `blocked`、クリアは `clear`＋`star`＋既存の「ついたね!」（おじの声 or ずんだもん）。**「ゴー!」は効果音だけ**（新しい声は増やさない）。 |
| **動きを減らす設定** | `AccessibilityInfo.isReduceMotionEnabled()`（react-native-web が `prefers-reduced-motion` に橋渡し）。ON のときは**首かしげの回転**と**ぴょんの弧**をやめ、同じ長さの間・まっすぐの移動にする。1歩ずつ進むこと自体は「観察」の核なので**残す**。①には影響しない。 |
| **実行の打ち切り** | 実行ループは世代番号（`runToken`）で管理。実行中に「おうちへ」を押しても、クリア後に「もういちど」を押しても、走っているループは次の歩の手前で静かに抜ける。 |
| **リサイズ** | 実行中にウィンドウが変わってもマス寸法を追える（`cellRef`）。 |
| **レイアウト** | 帯の高さ（64px固定）を**先に**確定させてから盤面のマス寸法を決めるので、上段・帯・盤面・方向パッドは絶対に重ならない。390×844 / 515×684 / 1280×800 ＋ さらに背の低い 360×640 × 2×2・4×4 × ①② で被りゼロ・スクロールゼロを実測（→ §16.2 の表）。 |
| **タップ領域** | ②の方向ボタン・ゴー! は**①と同じ一辺**、⌫ は **64×64 の実寸**。帯が縦を食っても、こどもが触るものは小さくならない（§4）。⌫ は四辺の端1pxを押しても効くことを実測（角は丸みぶん当たらない＝ふつうのボタンと同じ形）。 |
| **依存** | 新規 npm 依存ゼロ（react-native / react-native-web の標準 API のみ）。 |

### 16.7 実装ファイル

```

src/a11y.ts                      useReducedMotion()（AccessibilityInfo → prefers-reduced-motion）
src/game/generate.ts             queueCapacity() を追加し、Level.maxSteps に実際の最短手数から入れる
src/components/CommandQueue.tsx  「命令の列」の帯（空きマス・実行中の光り・⌫ 64×64）＋ 帯の寸法（高さ64px固定）
src/components/GoButton.tsx      十字のまんなかの「ゴー!」（緑のまる・0本ならうすく押せない）
src/components/DirPad.tsx        center / disabled を追加（①では従来と同じ描画）
src/screens/PlayScreen.tsx       ②の状態と実行ループ（1歩ずつ・止めない・ぴょんと戻る）＋ 縦の配りかた（§16.2）

```
