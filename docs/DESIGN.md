# おつかいめいろ — 設計ドキュメント

> 4歳の姪っ子のための、超やさしいプログラミング体験の知育アプリ。
> マスの上でアバターを動かし、りんごや「おばあちゃんの家（実写真）」に届ける。届いたら**おじの声**で「ついたね!」。
> 絵本『ルビィのぼうけん』の延長として、**順序立て（アルゴリズム）**と**うまくいかない→直す（試行錯誤・デバッグ）**の下地をつくる。

最終更新: 2026-07-11

企画の全体像・案の比較は [IDEAS.md](IDEAS.md) を参照（本アプリは「案1 ○○ちゃんのおつかいめいろ」を第1作にしたもの）。

---

## 0. 配布方針（Webファースト・確定）

**決定: まず Web で配る。** Expo の web ビルド（静的サイト）を書き出し、その URL を姪っ子の端末（を持つ家族）に渡す。ブラウザで開き、**ホーム画面に追加**すれば、アドレスバーの無い全画面で“アプリのように”遊べる（iOS / Android とも対応）。ネイティブアプリ（App Store / Expo Go）は**同じコードから後日**出す。

- **なぜ Web ファーストか**
  - Apple Developer 登録（年約 $99）や審査なしで、**今すぐ実機で試せる**。身内配布・テスト段階に最適。
  - 端末を選ばない（iPhone / iPad / Android / PC どれでも URL 一つ）。姪っ子・祖母・おじの環境差を吸収できる。
  - Expo は同一コードから web / iOS / Android を出せるので、**Web 先行でも将来のネイティブ化は地続き**。
- **ホスティング: GitHub Pages** を想定。`npx expo export --platform web` で `dist/` を書き出し、Pages に載せて URL 配布（限定 URL でよい）。
- **渡し方**: URL を送る → Safari / Chrome で開く → 共有メニューから「ホーム画面に追加」→ アイコンから全画面起動。
- **オフライン性は維持**: バックエンド・アカウント・通信は引き続きゼロ。初回だけ静的アセットを取得し、**写真・音声・進捗は端末内（ブラウザ内）に留める**。§1「完全オフライン」の方針は Web でも保つ（サーバへ送らない）。将来 Service Worker を足せば再訪時の完全オフライン起動も可能（MVP 対象外）。

## 1. コンセプト

受け身の「見る」から、**自分で考えて動かす**へ。それを4歳が、コードもリアルタイム操作も使わずに体験できる形にする。

- **核となる体験:** マス目の世界でアバターを目的地まで動かす。届いたら大歓声、外れてもキャラが首をかしげるだけ。
- **育てたい力:** ①言われた順に物事を並べる（順序立て）、②思ったとおりにいかなかったら直す（試行錯誤）。就学後に必修化される「順序・くりかえし」の入口。
- **キャラ設定:** アバターは「**言われた順にしか歩けないおともだち**」。だから間違いは“ロボットの正直な実行”として腹落ちする（＝デバッグの原体験）。

### この子だけの世界地図（最大の差別化）

作り手（おじ）と姪っ子は遠方でほとんど会わない。汎用アプリには絶対に作れない要素で埋める。

- ゴールを**実在の写真**（祖母の家・この前いった公園）に。
- 掛け声「ゴー!」「ついたね!」を**おじの録音声**に。
- 主役は姪っ子本人（既存キャラIPは使わない）。

### 立ち位置（重要・2つの前提）

| 前提 | 中身 |
|---|---|
| **プライバシー: 完全オフライン** | MVPは**単一端末で完結**。写真・音声・進捗はすべて**端末内のみ**に保存し、**外部送信・アカウント・通信はゼロ**。これが1本目（kore-daijobu）との一番の違い。 |
| **著作権** | アンパンマン等の既存キャラは不可。素材は**自作／AI生成／フリー素材（いらすとや等）／おじの録音**のみ。 |

## 3. 二段階の遊びモード（本アプリの背骨）

4歳には「先にまとめて計画する」がやや難しい。そこで**やさしい方から2段階**で用意し、MVPは①だけを作り切る。

| | ① タップで即動く【MVP】 | ② ならべてゴー（キュー方式） |
|---|---|---|
| いつ | 最初から | ①に慣れてから（フェーズ4） |
| グリッド | 2×2〜3×3 / 1〜2手 | 3×3〜 / 数手 |
| 操作 | 方向ボタン → その場で1マス動く | 矢印を並べる → 「ゴー!」で一気に実行 |
| 体感 | 押す→動く（因果・空間把握） | **計画→実行→観察→修正**のループ |

②のプログラミング的思考ループ:

```
   けいかく          じっこう          かんさつ          しゅうせい
  （ならべる）  →  （ゴー!）  →  （とどいた?）  →  （ならべ直す）
        └────────────────── くりかえし ──────────────────┘
```

> ①でも「押す＝1つの命令」を体で覚えるので、②への地続きの前段になる。②は同じ移動処理・同じレベルデータをそのまま使い、UI（命令キュー）だけ足す設計にする。

## 4. 4歳UX原則（全画面の共通ルール）

- **文字に頼らない** … 操作は音声・アイコン・写真で伝える。ひらがなは“読める子には嬉しい”装飾程度。
- **巨大タップ領域** … 方向ボタンは指1本で確実に押せる大きさ（実装上64pt以上、実際はもっと大きく）。押し間違い防止に間隔をあける。
- **単発タップ中心** … こども操作にドラッグ・長押しを使わない（親ゲートを除く）。指の接触切れに強い。
- **誤操作に寛容** … 動けない方向を押しても何も壊れない。Undoが要らない設計。
- **罰・ゲームオーバーなし** … タイマー・ライフ・減点なし。外れ＝「もういちど」の入口。失敗表現はキャラが**首をかしげる**だけ。
- **短いセッション** … 1レベル数十秒。いつでも中断・再開。連続プレイを煽らない。
- **過度な射幸性なし** … ガチャ・コイン・ランキング・広告なし。ご褒美は「写真＋おじの声＋ちいさな演出」に限定。
- **感覚にやさしく** … 強い点滅・大音量・急な動きを避ける。音量は控えめを既定に。

## 5. MVP スコープ

### コアループ（これ1つを作り切る）

```
レベルをえらぶ
  → 方向ボタンをタップ → アバターが1マス動く（①タップモード）
  → ゴール（りんご/写真）に届く
  → 写真ズーム＋ちいさな紙吹雪＋おじの声「ついたね!」
  → 「もういちど」/「つぎへ」
```

### やること（MVPに入れる）

- ①タップモードのプレイ画面（グリッド描画・アバター・方向ボタン・1マス移動・障害物と壁の判定）
- ゴール到達 → 祝福演出（既定でも成立：既定イラスト＋既定SE）
- 同梱レベル **3〜5個**（2×2から3×3へゆるやかに）＋ 写真つきの**レベルえらび**画面
- **おとなモード（親ゲートの奥）: ゴール写真の差し替え**（＝差別化の核。必須）
- 端末内保存（上書きした写真・音声のパス、任意で進捗）

### やること・努力目標（できれば入れる）

- **おじの声の録音／差し替え**（expo-audio）。※録音UIが最大の新規リスクなので、**まずは事前収録した音声ファイルを同梱**して鳴らす形で成立させ、録音UIは余力があれば。
- ハプティクス（タップ・到着の触覚）
- ごく短いBGM

### やらないこと（MVPでは入れない = 次段階）

- ②キュー方式（並べてゴー）… フェーズ4
- 「くりかえし（ループ）」ブロック … 将来
- **おとなモードでのレベル構造の編集**（マス・障害物のGUI編集）… 当面レベルはJSON同梱で、追加・変更はコード側で行う
- 進捗ロック（前をクリアしないと次に行けない等）… MVPは全レベル自由に遊べてよい
- **ネットワーク・バックエンド・アカウント全般**（遠隔レベル送信は第2フェーズ）

## 6. 画面の流れ

### こども側（文字ゼロで進める）

```
[タイトル]
  大ボタン「あそぶ」（アイコン＋読み上げ）
  隅にちいさな歯車 … 3秒長押しで [おとなモード]（親ゲート）
     │ タップ
     ▼
[レベルえらび]   ※ゴール写真つきの大きなカードを横スクロール。文字は最小、タップで音声読み上げ
     │ カードをタップ
     ▼
[プレイ（①タップモード）]
  上段: ゴールの写真/イラスト（「ここまで いこう」）
  中段: 2×2〜3×3 のグリッド ＋ アバター（＋障害物）
  下段: ◀ ▲ ▼ ▶ の巨大ボタン
     ・押す → 動ける向きなら1マス移動（てくてくSE）
     ・壁/障害物で動けない → キャラが首をかしげる＋やさしい「?」音（失敗ではない）
     ・ゴール到達 → 写真ズーム＋紙吹雪＋おじの声「ついたね!」
     │
     ▼
[クリア]  「もういちど」／「つぎへ」／「おうちへ（レベルえらび）」
```

### ②キュー方式（フェーズ4での差分だけ）

```
[プレイ（②ならべてゴー）]
  下段の矢印を押す → 画面上部の「命令の列」に積まれる（例: ▶ ▶ ▲）
  「ゴー!」→ 先頭から1マスずつ実行（アニメとSEを同期）
  外れても首をかしげるだけ → 「もういちど」で列を空にして組み直し
```

### おとな側（親ゲートの奥）

```
[おとなモード]   ※歯車を3秒長押しで入る（4歳が偶発しにくい操作）
  ・レベルごとに「ゴールの写真をえらぶ」（カメラロールから / expo-image-picker）
  ・「おじの声を差し替える」（録音 or 同梱音声から選ぶ）  ※MVPは努力目標
  ・もどる
  破壊的な操作（差し替え・消去）には確認を1枚はさむ（子どもの誤操作で壊れないように）
```

## 7. データモデル

**レベル定義（グリッド・スタート・ゴール・障害物）をJSONで**持ち、写真・音声パスは端末内のみ。

### レベル定義（アプリ同梱の静的JSON `levels.json`）

```jsonc
{
  "id": "level-01",
  "title": "おばあちゃんのおうちへ",   // 表示・音声読み上げ用
  "cols": 2,                          // 横のマス数
  "rows": 2,                          // 縦のマス数
  "start": { "x": 0, "y": 1 },        // アバター初期位置（x=列/0起点, y=行/0起点）
  "goal":  { "x": 1, "y": 0 },        // ゴールのマス
  "obstacles": [ { "x": 0, "y": 0 } ],// 通れないマス（無ければ空配列）
  "mode": "tap",                      // "tap"（①即動く） | "queue"（②並べてゴー）
  "maxSteps": 2,                      // ②で並べられる最大手数（①では無視）
  "goalImage": null,                  // 差し替え前は null → 既定イラスト（りんご/おうち）
  "goalVoice": null                   // 差し替え前は null → 既定SE
}
```

**座標と移動の約束:** `x` は列（左→右）、`y` は行（上→下）、どちらも0起点。▲=y−1／▼=y+1／◀=x−1／▶=x+1。盤面の外・障害物のマスへは移動しない（＝首をかしげる）。

### おとなモードの上書き（`AsyncStorage`）

同梱JSONは書き換えず、**差分だけ**を端末内に保存して重ねる。

```jsonc
// key: "levelOverrides"
{
  "level-01": {
    "goalImage": "file:///.../photos/obaachan.jpg", // image-pickerで選んでコピー保存
    "goalVoice": "file:///.../voices/tsuitane.m4a"   // 録音 or 同梱から選択
  }
}
```

### 保存場所とプライバシー

| データ | 保存先 | 外部送信 |
|---|---|---|
| レベル定義（構造） | アプリ同梱JSON | しない |
| 上書き差分・進捗（任意） | `AsyncStorage` | しない |
| ゴール写真 | `expo-file-system` のドキュメント領域にコピー | **しない** |
| おじの声 | 同上（録音 or 同梱） | **しない** |

> **すべて端末内で完結。通信・アカウント・クラウドは一切使わない。** カメラロールの写真は「アプリ内にコピーを1枚持つ」だけで、どこにも送らない。

## 8. 技術構成

1本目 kore-daijobu と**同じスタックを再利用**（Expo SDK 57 / React Native / TypeScript、`src/screens`・`src/components`・`src/data` 構成、Node 20.20.0）。バックエンド（Supabase）は**使わない**。

| 役割 | 技術 | 用途 |
|---|---|---|
| アプリ基盤 | **Expo SDK 57 / React Native / TypeScript** | kore-daijobu と同一。実機は Expo Go でテスト |
| 画面遷移 | @react-navigation/native + native-stack | タイトル→レベルえらび→プレイ→クリア／おとなモード |
| アニメーション | **react-native-reanimated** | アバターのマス移動、ぷるん着地、紙吹雪・ズームの祝福演出 |
| 効果音・音声 | **expo-audio** | 掛け声・SE再生、おじの声の**録音** |
| 写真取り込み | **expo-image-picker** | ゴール写真の差し替え（カメラロール／撮影） |
| ファイル保存 | **expo-file-system** | 選んだ写真・録音を端末内にコピー保存 |
| ローカル保存 | **@react-native-async-storage/async-storage** | 上書き差分・進捗の永続化 |
| 画像表示 | expo-image（または RN Image） | 写真・イラストの表示 |
| ハプティクス（任意） | expo-haptics | タップ・到着の触覚フィードバック |

> **実装前に必ず** Expo SDK 57 の公式ドキュメント（`https://docs.expo.dev/versions/v57.0.0/`）で各ライブラリの**最新の導入手順・API名**を確認する（reanimated の babel プラグイン設定、expo-audio の権限まわり等）。SDKごとにAPIが変わるため、記憶で書かない。

### Web対応の注意（Webファースト前提 / §0）

Expo は同一コードを web でも動かせるが、ブラウザ特有の制約がある。§0 の配布方針に伴い、以下を織り込む。

- **音声の自動再生制限（iOS Safari 等）** … ページ読み込み直後に勝手に音は鳴らせない。**ユーザーのタップを起点にした再生なら鳴る**ので、SE・掛け声は「ボタンを押した」「到着した（＝直前の操作起点）」タイミングで鳴らす設計にする。BGM の自動ループは避けるか、最初のタップで解禁する。
- **端末内保存の永続性** … RN の `AsyncStorage` は web では **`localStorage` 相当**になる。プライベートブラウズ・サイトデータ削除・ストレージ逼迫で**消える可能性**がある。MVP は「消えても遊びが壊れない」前提（進捗ロックなし）なので許容。写真の上書き等は容量が大きいので、web では IndexedDB / File API 側の扱いを検討（フェーズ2）。
- **写真・録音の取得** … expo-image-picker / expo-audio はネイティブ API 前提。web では **ブラウザ API（`<input type=file>` / `getUserMedia` / MediaRecorder）経由**になり、挙動・権限 UI が異なる。MVP（フェーズ1）はこれらを使わないので影響なし。フェーズ2 で web 実装を個別に用意する。
- **画面向き** … web はブラウザが向きを固定しないため、**縦持ち前提のレイアウト**（中央寄せ・最大幅制限）で横画面でも崩れないようにする。

### 開発環境メモ

- Node は **v20（.nvmrc: 20.20.0）**。macOS 既定の v16 では Expo が動かない。
- リポジトリ名は `otsukai-meiro`（アプリ名「おつかいめいろ」確定に伴いリネーム済み）。

## 9. ロードマップ（作る順番）

- **フェーズ0 雛形** … kore-daijobu を土台に Expo アプリ作成、ライブラリ導入。**先に reanimated の動作と expo-audio の録音/再生・マイク権限だけ検証**（IDEAS.md の指摘どおり最初に潰す）。
- **フェーズ1 タップ移動MVP** … グリッド描画・アバター・方向ボタン・1マス移動（reanimated）・壁/障害物で首かしげ・ゴール判定→祝福（既定イラスト＋既定SE）。同梱レベル3〜5個＋レベルえらび画面。
- **フェーズ2 パーソナライズ（差別化の核）** … おとなモード（親ゲート）→ **ゴール写真差し替え**（image-picker＋file-system＋AsyncStorage）。おじの声は**まず同梱ファイルで再生**、録音UIは余力で。
- **フェーズ3 磨き込み** … 演出（紙吹雪・キャラの表情）、効果音追加、レベル追加、ハプティクス。
- **フェーズ4 ②キュー方式** … 命令キューUI（矢印を並べる→ゴー）、逐次実行アニメ、「もういちど」。`mode` で ①/② を切替。
- **フェーズ5（将来・別スコープ）** … 「くりかえし（ループ）」ブロック → 遠隔でおじがレベルを作って送る（ここで初めてネットワーク＝§10）。

> ★ **最初のマイルストーン = フェーズ1完了。** ここで「遊べる」状態になり、**同梱の写真1枚＋既定音声だけでも姪っ子に渡せる**。差別化（本人の写真・おじの声）はフェーズ2で乗せる。

## 10. 素材計画（必要なものと調達）

### 画像

| 素材 | 用途 | 調達 |

| 姪っ子アバター | 主役キャラ（正面1枚でも可、余裕あれば向き別） | AI生成／いらすと風。※本人に似せるかは任意 |

### 効果音・音声

| 素材 | 用途 | 調達 |
|---|---|---|
| タップ音「ぽん」 | ボタン反応 | フリーSE（効果音ラボ等） |
| 移動音「てくてく」 | 1マス移動 | フリーSE |
| やさしい「?」音 | 動けない時 | フリーSE |
| ファンファーレ | ゴール到達 | フリーSE |
| 掛け声「ゴー!」「ついたね!」「もういっかい!」 | 差別化の核 | **おじの録音**（まず事前収録を同梱、後で差し替え） |
| BGM（任意・控えめ） | 雰囲気 | フリー／AI生成のループ |

> 素材の統一感（テイスト）だけ最初に決める（例: いらすとや寄りのやわらかい線・淡い色）。凝った演出は完成後に足す（MVPは「機能1つ・レベル数個」を厳守）。

## 11. 拡張の伸びしろ

- **②キュー方式**（フェーズ4で本体化）… 計画→実行→観察→修正の完全なループ。
- **「くりかえし（ループ）」ブロック** … 「▶を3かい」のようにまとめる → ループを絵として体験（IDEAS.md 案4／『ルビィ』の反復に接続）。
- **「かず」の芽** … 何手で着いたか・最短は何手かを控えめに見せる（軽い最適化の入口）。
- **レベルが増えやすい設計** … JSONに1件足すだけで増える。おとなモードの写真・声だけ変えても“新しいステージ”になる。
- **【第2フェーズ・要ネットワーク】遠隔でおじがレベルを作って送る** … おとなモードで作ったレベル（グリッド＋写真＋声）を書き出し、離れたおじが作って姪の端末に取り込む。ここで**初めてバックエンドが要る**（kore-daijobu の Supabase 経験を再利用）。写真・音声を扱うためプライバシー設計を伴う別スコープ。
